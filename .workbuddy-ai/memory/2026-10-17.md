## Follow-up: absolute-form request targets (proxy 404)

Root cause of the `ui_smoke` failure: with `HTTP_PROXY` set, the proxy forwards the
*second* request on a reused connection in RFC 9112 absolute-form
(`POST http://127.0.0.1:7788/jobs`). uvicorn's h11 parser does not split it, so
`scope["path"]` holds the whole URI and every route 404s (first request on a
connection works — that's why it looked intermittent).

Fix: `_AbsoluteFormMiddleware` + `_normalize_absolute_target` in `src/xdl/ui/app.py`
rewrites loopback absolute-form targets before routing; foreign authorities are left
alone for the Host guard. 5 regression tests in `tests/ui/test_serve.py`
(one end-to-end ASGI call that fails without the middleware).

Note: `scripts/ui_smoke.py` keeps `trust_env=False` — a loopback smoke should not go
through a proxy; the proxy path is covered by the ASGI test instead.

Gates: 311 tests, ruff, mypy strict, ui_smoke PASS.
