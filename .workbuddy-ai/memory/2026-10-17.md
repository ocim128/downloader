## Follow-up: absolute-form request targets (proxy 404)

Root cause of the `ui_smoke` failure: with `HTTP_PROXY` set, the proxy forwards the
*second* request on a reused connection in RFC 9112 absolute-form
(`POST http://127.0.0.1:7788/jobs`). uvicorn's h11 parser does not split it, so
`scope["path"]` holds the whole URI and every route 404s (first request on a
connection works — that's why it looked intermittent).

Fix: `_AbsoluteFormMiddleware` + `_normalize_absolute_target` in `src/xdl/ui/app.py`
rewrites loopback absolute-form targets before routing; foreign authorities are left
alone for the Host guard. 5 regression tests in `tests/ui/test_serve.py`
(one end-to-end ASGI call that fails without the middleware).

Note: `scripts/ui_smoke.py` keeps `trust_env=False` — a loopback smoke should not go
through a proxy; the proxy path is covered by the ASGI test instead.

Gates: 311 tests, ruff, mypy strict, ui_smoke PASS.

## First CI run exposed ambient-toolchain test deps

Committed as a87e141, pushed, CI failed on **both** ubuntu-latest and windows-latest (lint+mypy
passed) — so not a platform assumption, but a real latent bug in the suite:
`test_download_hls_failure_tail` and `test_download_hls_timeout_kills` expected
`HLS_FAILED` but got `HLS_REQUIRES_FFMPEG`. `require_ffmpeg()` falls back to
`shutil.which("ffmpeg")` when no `ffmpeg=` is passed; those two tests omitted it, so they
only passed on a machine with ffmpeg installed (this one has it via WinGet).
- Fixed by passing `ffmpeg="unused-by-sim"`, matching the three sibling tests.
- Audited all 6 `download_hls()` call sites: the other 4 were already hermetic.
- Verified by stripping the WinGet dir from PATH (`shutil.which` -> None): both fail
  pre-fix, pass post-fix. Lesson: any test that reaches an external binary must either
  pass the resolved path explicitly or stub `shutil.which`; never rely on the host PATH.
